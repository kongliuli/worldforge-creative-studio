## 一、环境要求

### 1.1 开发环境

| 项 | 版本 |
|----|------|
| .NET SDK | 10.0.100（`global.json` 锁定） |
| Node.js | 20 LTS+ |
| Ollama | 最新稳定版 |
| 推荐模型 | `phi4-mini` 或用户自选 |
| DB | SQLite（开发嵌入式）；PostgreSQL 16+（云 API 开发） |

### 1.2 用户环境（客户端）

| 项 | 最低 |
|----|------|
| 浏览器 | Chrome 120+ / Edge 120+ / Safari 17+ |
| RAM | 8 GB（本地 AI 建议 16 GB） |
| 磁盘 | 500 MB 应用 + 项目文件 |
| Ollama | 可选；无则规则引擎仍可用 |

## 二、CI/CD（GitHub Actions）

### 2.1 Workflow 矩阵

| 目标 | 命令 | Runner |
|------|------|--------|
| 单元测试 | `dotnet test` | ubuntu-latest |
| 前端构建 | `npm ci && npm run build` | ubuntu-latest |
| Server Docker | `dotnet publish -r linux-x64 -c Release` | ubuntu-latest |
| E2E | Playwright | ubuntu-latest |
| Electron（若启用） | `npm run electron:build` | windows-latest |

### 2.2 触发策略

| 事件 | 动作 |
|------|------|
| push main | test + build |
| pull_request | test + E2E |
| tag `v*` | publish Docker + Gumroad 产物上传 |

### 2.3 Docker 生产镜像

```dockerfile
# 概念 Dockerfile — API only
FROM mcr.microsoft.com/dotnet/aspnet:10.0 AS runtime
WORKDIR /app
COPY publish/ .
ENTRYPOINT ["dotnet", "WorldForge.Server.dll"]
```

PWA 静态资源：CDN 或同容器 `wwwroot/`。

## 三、性能目标

### 3.1 客户端

| 指标 | 目标 | 测量 |
|------|------|------|
| Web 冷启动 FCP | < 1.5s | Lighthouse |
| TipTap 章节加载 | < 100ms | Performance API |
| 笔记本地保存 | < 30ms | SQLite 写入 + debounce |
| @ 实体补全 | < 200ms | — |
| 单章矛盾检测 P95 | < 2s | CI 基准机 |
| 手稿树 1 万节点滚动 | 60fps | vue-virtual |
| PWA 安装后二次打开 | < 800ms | SW cache |

### 3.2 服务端（可选云）

| 指标 | 目标 |
|------|------|
| API P95 延迟 | < 200ms |
| 许可证验证 | < 100ms |
| 备份上传 10MB | < 5s（视网络） |

### 3.3 升级触发器

| 条件 | 动作 |
|------|------|
| 全文搜索 > 200ms（5 万笔记） | 引入 Meilisearch |
| 协作同步延迟 > 1s | 区域 WebSocket 节点 |
| WASM SQLite 写入 > 50ms | 切 Electron native SQLite |

## 四、测试策略

### 4.1 三层金字塔

| 层级 | 工具 | 内容 |
|------|------|------|
| 单元 | xUnit + NSubstitute | 领域规则、Contradiction 解析、Import 映射 |
| 集成 | WebApplicationFactory | License API、Backup API |
| E2E | Playwright .NET | 创建项目、写章节、@实体、检测矛盾 |

### 4.2 专项测试

| 专项 | 方法 |
|------|------|
| CRDT 一致性 | 双浏览器实例（Phase 2） |
| 离线恢复 | 断网 → 写作 → 刷新 → 数据仍在 |
| 导入回归 | Scrivener fixture 项目快照对比 |
| AI fixture | 已知矛盾必须检出 |

## 五、安全运维

| 层面 | 方案 |
|------|------|
| 认证 | JWT 15min + 刷新 30 天 |
| CSP | `script-src 'nonce-{random}' 'strict-dynamic'` |
| 速率限制 | 登录 5/min；CRUD 60/min |
| 密钥 | Azure Key Vault / GitHub Secrets |
| 依赖 | Dependabot；NUKE 或 `dotnet outdated` |
| 日志 | OpenTelemetry → 可选 Grafana Cloud |
| 备份 | PostgreSQL 日快照；用户 blob 不删仅标记 |

---

## 六、监控与告警

| 信号 | 阈值 | 动作 |
|------|------|------|
| API 5xx | > 1% 5min | PagerDuty / 飞书 |
| 许可证验证失败激增 | > 100/h | 防滥用调查 |
| Docker 内存 | > 80% | 扩容 |
| Gumroad Webhook 失败 | 任意 | 人工补单 |

**客户端**：可选 Sentry crash；**不上传手稿内容**。
