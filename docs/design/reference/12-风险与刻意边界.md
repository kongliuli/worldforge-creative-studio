# 12 — 风险与刻意边界

> **关联源文档**：`0705调研报告/AI笔记垂直场景/A-创意工作者工作室.md`、`ai笔记调研项目图景/细分场景/场景6-创意工作者-深度调研.md`、`ai笔记调研项目图景/补充场景-核心共性与技术架构复用.md`、`0705调研报告/03-公司资产复用补充.md`

---

## 本文档用途

汇总各源调研中的 **风险、红线与易犯错误**，供立项评审与开发过程中反复对照。  
若与功能优先级冲突，**本文档刻意边界优先于个别功能的「想做」**。

---

## 一、产品风险

### 1.1 竞争窗口：12 个月

| 项 | 说明 |
|----|------|
| **风险** | Ishvana（$99）、PlotForge（$69–79）计划 2026 年内发布，抢占「Scrivener 替代品 + 本地 AI」心智 |
| **等级** | 高 |
| **应对** | 12 月内 MVP 上线；**矛盾检测**为差异化核心，非功能数量堆叠 |
| **勿做** | 为了「功能表对标 World Anvil」延误上线 |

### 1.2 Scrivener 用户惯性

| 项 | 说明 |
|----|------|
| **风险** | 15 年用户习惯、$60 价格锚点 |
| **等级** | 中 |
| **应对** | **Scrivener 导入器质量**决定转化；以痛点（无世界构建、无 AI、无 Linux）切入，非正面 PK |
| **架构要求** | 导入映射覆盖 Binder + 角色表；见 [03-数据模型与存储](./03-数据模型与存储.md) §八 |

### 1.3 AI 定位滑坡

| 项 | 说明 |
|----|------|
| **风险** | 滑向整章代写 → 版权争议、与 ChatGPT 同质化 |
| **等级** | 高 |
| **刻意边界** | ✅ 矛盾检测、补全、语义搜索；❌ 整章生成、无审查 AI 入库 |
| **KPI** | 矛盾检测周活 ≥60%，**不是** AI 生成字数 |

### 1.4 CandyAI / 陪伴产品边界

| 项 | 说明 |
|----|------|
| **风险** | persona-templates 复用导致 scope 滑向陪伴聊天 |
| **等级** | 中 |
| **刻意边界** | 模板仅用于 Entity 预填；不做 daily chat、不做情感依赖 UX |
| **参考** | [10-公司资产对接](./10-公司资产对接.md) §4.3 |

### 1.5 「世界构建 ≠ 写作侧栏」

| 项 | 说明 |
|----|------|
| **风险** | 做成「Scrivener + 笔记侧栏」而非真正实体系统 |
| **等级** | 中 |
| **应对** | 实体类型系统 + 关系图谱 + 时间线 + 跨章检测 **同库**；Ishvana 式主张 |

## 二、技术风险

### 2.1 MAUI 月 12 前禁止

| 项 | 说明 |
|----|------|
| **风险** | MAUI 工具链成熟度不足，拖慢 MVP 3+ 月 |
| **等级** | 高 |
| **刻意边界** | 月 0–12：**PWA / Electron only** |
| **退出标准** | MAUI 速度持续 < Web 30% → 继续 Electron |

### 2.2 MVP 引入 Yjs / CRDT

| 项 | 说明 |
|----|------|
| **风险** | 3 个月做不成核心差异化，沦为「又一个笔记应用」 |
| **等级** | 高 |
| **刻意边界** | MVP **无** Yjs；Phase 2 再上 |
| **来源** | NET10 报告建议三 |

### 2.3 SQLite 部署形态选型

| 项 | 说明 |
|----|------|
| **风险** | PWA WASM 文件系统受限 → Scrivener 导入体验差 |
| **等级** | 中 |
| **应对** | 月 4–6 评估 Electron；或 zip 上传导入 |
| **决策点** | File System Access API 能否读 `.scriv` 目录 |

### 2.4 本地 AI 性能

| 项 | 说明 |
|----|------|
| **风险** | 中低端设备 Ollama > 5s → 用户关 AI → 隐私承诺落空 |
| **等级** | 中 |
| **应对** | 规则引擎快速路径；2s SLA；全书扫描异步队列 |
| **降级** | Ollama 不可用时仍可用规则检测 |

### 2.5 矛盾检测误报

| 项 | 说明 |
|----|------|
| **风险** | 误报过多 → 用户关功能 |
| **等级** | 中 |
| **应对** | FalsePositive 标记反馈；规则 / LLM 分层；Beta 调 Prompt |
| **目标** | 误报率 < 20%（Beta） |

### 2.6 向量搜索规模

| 项 | 说明 |
|----|------|
| **风险** | 超大项目 Embedding brute-force 变慢 |
| **等级** | 低（MVP 期） |
| **应对** | 5 万笔记前够用；触发器见 [11-部署运维与性能](./11-部署运维与性能.md) |

## 三、商业风险

### 3.1 买断 LTV 有限

| 项 | 说明 |
|----|------|
| **风险** | 一次性 $69–99 后无 recurring |
| **等级** | 中 |
| **应对** | 大版本升级费 + AI 云模块 $19/年 |
| **Year 1** | **PMF 验证**，基准 400 用户仍亏（≈¥22 万 vs ¥50 万成本） |

### 3.2 市场地域

| 项 | 说明 |
|----|------|
| **风险** | 中文 TTRPG/网文付费习惯弱于欧美 |
| **等级** | 中 |
| **刻意边界** | **全球英文首发** GTM；中文 i18n 预埋非主销 |
| **渠道** | Reddit、PH、NaNoWriMo — 非小红书 |

### 3.3 定价锚点

| 项 | 说明 |
|----|------|
| **风险** | 超过 $100 需更强差异化 |
| **等级** | 低 |
| **应对** | 早鸟 $69；正式 $89–99 对标 Ishvana/PlotForge |

## 四、组织与战略风险

### 4.1 五场景 scope creep

| 项 | 说明 |
|----|------|
| **风险** | 同时做创意 + 遗产 + 健康 → 资源分散 |
| **等级** | 高 |
| **刻意边界** | **月 0–12 只做 A 方案** |
| **引擎** | 代码可复用；GTM / 品牌不可并行 |

### 4.2 双主 bet（飞书 + WorldForge）

| 项 | 说明 |
|----|------|
| **风险** | 同一 2–3 人团队并行两条赛道 |
| **等级** | 高 |
| **刻意边界** | 产品层 **零复用**；选一个主 bet |
| **例外** | NewAPI/订阅层可由平台同学并行建设 |

### 4.3 Agent 过度承诺

| 项 | 说明 |
|----|------|
| **风险** | Agent 未开发却营销「智能角色对话」 |
| **等级** | 中 |
| **刻意边界** | MVP 称「本地矛盾检测」；Agent 写 roadmap，Phase 2 后面世 |
| **Phase 1 叙事** | 辅助工具，非智能体伴侣 |

### 4.4 多场景稀释品牌

| 项 | 说明 |
|----|------|
| **风险** | 称「通用笔记引擎」导致认知混乱 |
| **等级** | 中 |
| **应对** | 独立品牌 WorldForge；B 方案 LegacyVault 另品牌 |

## 五、合规与伦理

### 5.1 AI 内容版权

| 项 | 说明 |
|----|------|
| **风险** | AI 生成内容版权归属模糊 |
| **等级** | 低（若不做生成） |
| **刻意边界** | 定位为 **辅助工具**，非替写 |

### 5.2 健康 / 遗产误用

| 项 | 说明 |
|----|------|
| **风险** | 用户把 WorldForge 当医疗/法律工具 |
| **等级** | 低 |
| **应对** | 免责声明；Creative 场景无 Death Tech / HIPAA 承诺 |

## 七、评审会议必问五题

1. 本 sprint 是否增加 **延后项**（协作 / MAUI / 插件 / 代写）？
2. 矛盾检测路径是否仍 **< 2s P95**？
3. 是否有 **无 Ollama 仍可用的** 核心价值？
4. 导入 Scrivener 的 **真实项目** 测过吗？
5. 是否在未达 PMF 指标时启动 **B 方案 GTM**？

任一题答案异常 → 回到 [09-MVP范围与路线图](./09-MVP范围与路线图.md) 重新对齐。
